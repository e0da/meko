## Evidence

The filesystem tests exercise independent copy-on-write saves, collision/lock protection, reference restrictions, external-link rejection, version-pinned dependency records, upgrade/removal/file diffs, manifest-only Core construction and hash mismatch rejection, and flag copying without overwriting different content.

Native CKAN window inspection confirmed the Green mod list and the Blue mod list after reopening. An attempted CLI switch while CKAN was open was rejected by the registry-lock check. The CLI waits for the dedicated Wine server to exit before handing GUI launch back to macOS; this addresses the observed remote-terminal graphics-context failure. A retry during verification briefly created a second GUI; its lock prompt was canceled without forcing access, then both windows were closed before re-testing.

Green was launched through its actual Mac KSP.app. Its fresh KSP.log recorded all four `Load(Texture): Meko/Flags/...` entries and the transition from LOADING to MAINMENU. It was then quit. This proves startup and texture loading, not visual flag-picker appearance, mod compatibility or campaign gameplay.

The state records capture the pre-launch baseline. A later game run can change settings or generated GameData files; capture a new record before promoting subsequent changes.

## Sources and limits

The stock selection uses locally installed Steam depot manifests. The reader follows the framing and fields documented by [ValvePython/steam's manifest reader](https://github.com/ValvePython/steam/blob/master/steam/core/manifest.py) and [content manifest schema](https://github.com/ValvePython/steam/blob/master/protobufs/content_manifest.proto).

The historical recipe and registry came from the user's old Kranston Windows installation. Mac compatibility and old archive availability remain unqualified. No mod install/removal or silent version upgrade was performed. Custom flag PNGs were copied unchanged from iCloud-backed Documents into local assets and the three selected instances; they were not published.

Recovery copies remain on the same disk. They protect this migration, not against losing the disk. The machine had about 17 GiB available before setup, so copying uses clonefile without a full-copy fallback.

## Delivery effort

The initial estimate was 30–60 minutes and 3 points. Scope grew to include recovered iCloud flags and a manifest-driven stock reference, plus a regression fix for remote Wine-to-GUI handoff. Recovery snapshots and source records were captured before changing the playable copies. Active work versus waiting was not instrumented separately; no precise active-time claim is made.
